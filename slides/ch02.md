# 2.1 把问题变成搜索

## 状态、动作与目标
- **状态**：问题此刻的样子（师傅在哪个路口）
- **动作**：从一个状态到另一个状态（走一段路）
- **目标**：要到达的状态（客户家）
- **代价**：每个动作的花费（公里数）

::: notes
把实际问题抽象成这四样东西，是用搜索解决问题的第一步，也是“计算思维”的核心。
:::

## 状态空间与搜索树
!mermaid 1
- 所有状态及其连接构成**状态空间**
- 从起点展开的过程画成**搜索树**
- S 维修站 → G 客户家，有好几条路

::: notes
这张小地图后面做广度优先和 A* 的“算一算”都要用，请学生记住各段的公里数。
:::

## 算一算：组合爆炸
- 八数码：可达状态 **181440** 种，几秒搜完
- 10 户送货：**3628800** 种顺序
- 20 户：约 **2.4 × 10¹⁸** 种，每秒 10 亿种要 70 多年
- 围棋：约 **2.08 × 10¹⁷⁰** 种局面，宇宙原子约 10⁸⁰

::: notes
状态数随问题规模急剧增长，叫组合爆炸。所以不能“全部试一遍”，要有聪明的搜索方法，这就是启发式搜索和剪枝要解决的问题。
:::

# 2.2 盲目搜索

## 广度优先与深度优先
| | 广度优先 | 深度优先 |
|---|---|---|
| 怎样找 | 一层一层地找 | 一条路走到黑，再回头 |
| 找到的路线 | 步数最少 | 不一定最短 |
| 内存 | 占得多 | 占得少 |
| 比喻 | 水波一圈圈扩散 | 走迷宫摸着墙走 |

::: notes
两者都不知道目标在哪个方向，所以叫盲目搜索。一致代价搜索按“已走的路程”从小到大扩展，能找到路程最短的路线。
:::

## 算一算：广度优先搜索
- 队列：S → A、B → D → C → G
- 找到：S → A → D → G，3 段路，**11 公里**
- 步数最少，但**不是路程最短**
- 每步代价相同时，才保证最短

::: notes
按字母顺序排队，依次取出 S、A、B、D、C、G。两条路都是 3 段，广度优先不管每段路有多长，所以找到了更远的那条。
:::

# 2.3 启发式搜索

## 启发函数：给搜索一个方向感
- **启发函数 h**：估计“还剩多远”，比如直线距离
- **贪婪搜索**：只看 h，容易被“近”骗
- **A* 搜索**：f = g（已走的）+ h（还剩的）
- h 不高估，A* 就能找到最短路线

::: notes
难点：A* 的 f 值怎样算。强调 g 是实际走过的路程，h 是估计值，两者相加才是“经过这里的总路程估计”。
:::

## 算一算：A* 搜索
| 步骤 | 展开 | 新候选（g + h = f） |
|---|---|---|
| 1 | S | A：2 + 4 = 6；B：3 + 5 = 8 |
| 2 | A | D：9 + 1 = 10 |
| 3 | B | C：5 + 3 = 8 |
| 4 | C | G：9 + 0 = 9 |
| 5 | G | 找到：S → B → C → G，**9 公里** |

::: notes
A* 一开始被 A 的“近”吸引过去看了一眼，算出经过 A 至少要 10 公里后，就转回了 B 那边。和广度优先的 11 公里对比。
:::

# 2.4 博弈搜索

## 极小极大：假设对手也很聪明
!mermaid 2
- 轮到我：选分数**最大**的（MAX）
- 轮到对手：他选对我**最小**的（MIN）
- 从下往上算出最好的一步

::: notes
下棋和找路不同：有一个和你作对的对手。极小极大的精髓是“不指望对手犯错”。
:::

## 算一算：一棵小博弈树
| 我的走法 | 对手应对后的分数 | 对手会选 |
|---|---|---|
| 甲 | 3、12、8 | 3 |
| 乙 | 2、4、6 | 2 |
| 丙 | 14、5、2 | 2 |

- 在 3、2、2 中选最大：走**甲**，保证至少 3 分

::: notes
丙里有全场最高的 14 分，很诱人，但对手会选 2。剪枝：算到乙的第一个分支是 2，已经比甲的 3 小，乙后面的分支不用再算。
:::

## 动手试一试：井字棋
!sim tic-tac-toe
- 和极小极大算法下一局
- 它从不输，最多平局
- 看它为每一步算出的分数

::: notes
井字棋的局面少，计算机能搜完整棵树。国际象棋、围棋搜不完，就要靠剪枝、估值函数，以及神经网络。
:::

## 从“深蓝”到 AlphaGo
- 1997 年“深蓝”：强大的搜索 + 专用硬件
- 2016 年 AlphaGo：搜索 + **神经网络**判断局面
- 搜索仍是核心，“往哪里搜”交给学出来的模型
- 详见第 8 章

::: notes
深蓝靠强大的搜索和专用硬件，评估局面的规则是人写的。AlphaGo 用神经网络判断“哪步棋值得搜”“这个局面谁占优”。
:::

# 2.5 知识表示

## 三种知识表示方法
- **产生式规则**：如果……那么……
  - 如果空调不制冷且外机不转，那么检查电容
- **语义网络**：点表示概念，带名字的线表示关系
- **知识图谱**：海量的**三元组**（头实体，关系，尾实体）

::: notes
产生式规则是专家系统最常用的表示方法；语义网络是知识图谱的前身；知识图谱可以看作超大规模的语义网络，用在搜索、推荐、问答和风控中。
:::

## 语义网络
!mermaid 3
- 点：空调、家用电器、室外机、电容
- 线：“是一种”“组成部分”“需要”
- 可以顺着箭头**继承**：格力 KFR-35 需要电源

::: notes
格力 KFR-35 是一种空调，空调是一种家用电器，家用电器需要电源，所以计算机能推出格力 KFR-35 需要电源，不用一条条写。
:::

## 算一算：顺着三元组找答案
- 问：鲁迅出生在哪个省？
- （鲁迅，出生地，绍兴）
- （绍兴，所属省份，浙江）
- 答：**浙江**，这叫“多跳”查询
- 《呐喊》的作者出生在哪个省？要走几跳？

::: notes
答案：三跳。先从《呐喊》反查作者鲁迅，再查出生地，再查省份。
证书考点：人工智能应用工程师（高级）考核知识图谱的基本概念与应用，能用三元组表示一句话里的知识，知识图谱和大模型配合使用的好处。
:::

# 2.6 推理与专家系统

## 专家系统的组成
!mermaid 4
- **知识库**：专家的规则和事实
- **推理机**：用规则从事实推出结论
- **解释器**：回答“为什么”
- 还有综合数据库、知识获取、人机接口

::: notes
MYCIN 是 20 世纪 70 年代斯坦福大学开发的专家系统，帮助医生诊断细菌感染并推荐抗生素。盲评中方案可接受率约 65%，与斯坦福医学院教员相当，但最终没有在临床上正式使用。
:::

## 正向推理与反向推理
| | 正向推理 | 反向推理 |
|---|---|---|
| 方向 | 由因到果 | 由果找因 |
| 起点 | 已知事实 | 先假设一个结论 |
| 例子 | 有毛发、吃肉、黄褐色、黑条纹 → 是虎 | 假设是斑马 → 逐个问证据 |
| 适合 | 事实已经齐全 | 要一步步向用户提问 |

::: notes
难点：区分两种推理。对照医生：看了所有症状下诊断是正向；怀疑某病，开检查去验证是反向。
反向推理要先猜对假设，猜错了要换一个重来。
:::

- 再用反向推理：假设一种动物，回答它的提问

::: notes

:::

## 专家系统的局限
- **知识获取难**：专家的经验说不清、写不全
- **脆弱**：遇到规则外的情况就不会
- **难维护**：规则多了互相冲突
- **不会学习**：不能从新数据中改进

::: notes
这些局限导致了第二次低谷，也引出了第 3 章的机器学习：让计算机自己从数据中学规律。
:::

## 怎样选择解决问题的方法
| 问题 | 方法 |
|---|---|
| 判断能不能免费保修 | 规则 |
| 根据运行数据预测哪个零件坏了 | 机器学习 |
| 听懂客户的口语描述，整理成维修单 | 大模型 |
| 给 30 张维修单排路线 | 搜索 |

::: notes
实际系统常把几种方法组合起来：大模型听懂客户的话，机器学习预测故障，规则判断保修政策，搜索排路线。可以组织 3 分钟小组讨论，请学生给自己单位的一个问题选方法。
:::
