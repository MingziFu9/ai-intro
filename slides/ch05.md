- 中文处理的第一步往往是分词。
- 今天常用的中文分词工具（比如 jieba、哈工大 LTP）都是统计或深度学习方法，准确率……

::: notes
中文处理的第一步往往是分词。最简单的分词方法，是拿一本词典，从句子开头开始，每次尽量切出词典里最长的词，这叫最大匹配法。
今天常用的中文分词工具（比如 jieba、哈工大 LTP）都是统计或深度学习方法，准确率在 95% 以上。不过大模型处理文字时，并不完全按“词”来切，而是按 Token 来切，这一点在 5.3.2 节再讲。
:::

::: notes
词向量（Word Vector）换了一种思路：用一串几十到几百个小数来表示一个词，并且让意思相近的词，这串数字也相近。你可以把每个词想象成一张“词语地图”上的一个点，地图上，“手机”“电脑”“屏幕”挤在一起，“香蕉”“橙子”“榴莲”挤在另一处，“酒店”“前台”“房间”又在另一处。
词向量是怎么得到的？不是人一个个设定的，而是从海量文本里学出来的。基本的想法是：经常出现在相似上下文里的词，意思也相近。“我买了一部新____”，空格里常填“手机”“电脑”，很少填“香蕉”。2013 年，谷歌的米科洛夫（Tomas Mikolov）等人提出了 Word2Vec 方法，用一个简单的神经网络在几十亿词的文本上做“填空练习”，很快就能学出高质量的词向量，从此词向量被广泛使用。
怎样衡量两个词向量“近不近”？常用的是余弦相似度（Cosine Similarity）：看两个向量的方向是不是一致。方向完全相同，余弦相似度是 1；互相垂直，是 0；方向相反，是 −1。
词向量还有一个神奇的性质：词和词之间的关系，可以用向量的加减来表示。最有名的例子是：
> 国王 − 男人 + 女人 ≈ 女王
“国王”减去“男人”，剩下的大致是“王室”的意思，再加上“女人”，就得到了“女王”附近的位置。同样，“北京 − 中国 + 日本 ≈ 东京”。这说明词向量确实学到了一部分词语之间的意义关系。
不过，早期的词向量有一个缺点：一个词只有一个向量。“苹果”不管是指水果还是指手机，都是同一个点，只能落在两类词中间的某个位置。后来的语言模型会根据上下文给同一个词不同的向量：“我吃了一个苹果”里的“苹果”靠近水果，“我买了一部苹果”里的“苹果”靠近手机。这要用到 5.4 节的注意力机制。
:::

## 5.3.1 语言模型：预测下一个词

- 这种“预测下一个词、接上去、再预测下一个”的生成方式，叫自回归生成。
- 训练语言模型很方便：不需要人工标注。

打字时，输入法会猜你接下来要打什么：输入“今天天气”，它提示“很好”“怎么样”；输入“生日”，它提示“快乐”。这背后就是一个语言模型。
语言模型（Language Model）做的事情可以用一句话概括：根据前面的文字，预测下一个词是什么。更准确地说，它给出的是下一个词的概率：
这种“预测下一个词、接上去、再预测下一个”的生成方式，叫自回归生成。今天的大模型，不管是写文章、回答问题还是写代码，本质上都在做这件事：一个 Token 接一个 Token 地往外“吐”字。你在大模型产品里看到回答是一个字一个字“打”出来的，原因就在这里。
训练语言模型很方便：不需要人工标注。随便拿一段文字，遮住后面的部分，让模型去猜，正确答案就是原文本身。这就是第 3 章讲的自监督学习。互联网上有数不清的文字，都可以拿来当练习题，所以语言模型能用非常多的数据来训练。
“只会猜下一个词”听起来很简单，为什么能学会那么多本领？因为要猜得准，模型就必须“懂”很多东西：要猜出“中国的首都是____”，它得知道地理知识；要猜出一道算术题后面的答案，它得会算术；要接着写一段代码，它得懂编程。在足够多的文字上练习“猜下一个词”，模型就把文字里蕴含的大量知识和规律都学进去了。
:::

## 5.3.2 Token：大模型读写的单位 { #532 }

- 大模型并不是一个字一个字、也不是一个词一个词地处理文字的，它用的单位叫 Token（中文……
- Token 和字数怎么换算，不同的模型不一样。
- Token 为什么重要？
- 第一，计费。
- 第二，上下文长度。

::: notes
大模型并不是一个字一个字、也不是一个词一个词地处理文字的，它用的单位叫 Token（中文常译作“词元”）。一个 Token 可能是一个汉字、一个常用词、一个英文单词，也可能是一个英文单词的一部分，还可能是一个标点符号。模型的“分词器”会按照训练时统计出来的规律，把文字切成一个个 Token：常见的组合合成一个 Token，少见的拆成几个。
Token 和字数怎么换算，不同的模型不一样。以 DeepSeek 为例，它的官方文档给出的大致换算是：1 个中文字符约 0.6 个 Token，1 个英文字符约 0.3 个 Token。实际用了多少，以模型返回的统计为准。
Token 为什么重要？因为它和两件事直接相关。
第一，计费。大模型的接口通常按 Token 收费，而且输入（你发给模型的内容）和输出（模型写出来的内容）分开计价，输出一般更贵。
第二，上下文长度。
:::

## 5.3.3 上下文长度：模型一次能看多少

- 模型在生成每一个 Token 时，能“看到”的前文是有上限的，这个上限叫上下文长度（Co……
- 可以把上下文窗口想象成一张办公桌：桌面上能摊开的资料是有限的，摊不下的就只能收起来，看不……
- 上下文长度不等于“记性”。

::: notes
模型在生成每一个 Token 时，能“看到”的前文是有上限的，这个上限叫上下文长度（Context Length），也叫上下文窗口，用 Token 数来衡量。你在对话里说过的话、上传的文件、模型自己的回答，全都要放进这个窗口。
可以把上下文窗口想象成一张办公桌：桌面上能摊开的资料是有限的，摊不下的就只能收起来，看不到了。早期的模型上下文只有几千个 Token，聊得久一点就“忘了”开头说过什么；今天主流的大模型一般支持十几万甚至上百万个 Token。比如 12.8 万个 Token，按 1 个汉字约 0.6 个 Token 换算，大约是 21 万个汉字，差不多是一本长篇小说的篇幅。
上下文长度不等于“记性”。对话结束后，模型并不会记住你，下次开始新对话时一切从零开始（有些产品提供了“记忆”功能，那是另外把信息保存下来，下次再放进上下文里）。而且，内容太多时，模型对中间部分的关注往往不如开头和结尾，重要的要求最好放在提示词的开头或结尾，或者再强调一遍。
:::

## 5.3.4 温度：选概率最大的，还是抽签

- 回到 5.3.1 节，模型给出了下一个字的概率，到底选哪一个？
- 每次都选概率最大的，叫“贪心”。
- 按概率抽签：概率大的容易被抽中，概率小的也有机会。
- 温度（Temperature）就是调节“抽签”随机程度的设置。
- 这就解释了情景导入里的问题：同一个问题问两遍得到不同答案，是因为模型在“抽签”。

温度（Temperature）就是调节“抽签”随机程度的设置。温度低（接近 0），概率大的更占优势，回答稳定、保守；温度高，各个选项的概率被拉平，回答更多样，但也更容易“跑偏”、出现奇怪的词。

## 5.3.4 温度：选概率最大的，还是抽签

| 用途 | 建议的温度 | 原因 |
|---|---|---|
| 翻译、信息抽取、数据整理 | 低，如 0～0.3 | 答案基本是确定的，需要稳定准确 |
| 问答、写摘要 | 中，如 0.3～0.7 | 既要准确，又要表达自然 |
| 写文案、起名字、头脑风暴 | 高，如 0.8～1.0 | 需要多样和新意 |

::: notes
读这句话：“小猫追老鼠，它跑累了。”“它”指的是谁？大多数人会觉得是小猫，因为追的一方更容易跑累。再读：“小猫追老鼠，它躲进了洞里。”这回“它”是老鼠。要弄懂“它”，必须回头去看句子里的其他词，并且判断哪个词最相关。
第 4 章的循环神经网络是一个词一个词往下读的，读到“它”的时候，“小猫”已经是好几个词以前的事了，只能靠“记忆”里残留的一点信息。注意力机制（Attention Mechanism）换了一种做法：读到每一个词时，都直接回头看一遍句子里的所有词，给每个词打一个“相关程度”的分数，相关的多看，不相关的少看，然后把它们的信息按分数混合起来，得到这个词“结合了上下文”的新意思。
就像你在一页书里找答案时，眼睛会自动在关键的几个词上多停留一会儿。打分越高的词，对理解当前这个词的帮助越大。读到“它”时，“小猫”“老鼠”的分数高，“，”的分数低；再结合“跑累了”，“小猫”的分数最高。
这正好解决了 5.2.3 节说的一词多义问题：“苹果”这个词，在“吃了一个苹果”里会更多地注意“吃”，在“买了一部苹果”里会更多地注意“一部”“买”，于是同一个“苹果”得到了不同的、和上下文相符的意思。
:::

第三阶段叫人类反馈强化学习（Reinforcement Learning from Human Feedback，RLHF）。同一个问题，让模型写出几个不同的回答，请标注人员按照“哪个更有用、更真实、更安全”排个序。用这些排序数据训练一个“打分模型”，再让大模型不断按照打分模型的评价改进自己的回答。“强化学习”的意思是通过奖励来学习，第 8 章会详细讲。

::: notes
